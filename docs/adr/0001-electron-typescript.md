# ADR 0001: Electron и TypeScript как основа приложения

- Статус: принято
- Дата: 2026-08-30

## Контекст

Приложению нужен единый настольный runtime для macOS на Apple Silicon, Windows и Linux,
двухпанельный интерфейс и доступ к потоковому вводу-выводу, системному хранилищу секретов и
сетевым протоколам. Команда должна иметь возможность независимо развивать интерфейс и
системную часть, сохраняя строгие контракты между ними.

## Решение

Использовать Electron, React, Vite и TypeScript со строгими настройками. Код разделяется на
main, preload, renderer и shared. Main владеет системными ресурсами и провайдерами, renderer
содержит только UI, preload предоставляет узкий типизированный мост, shared содержит только
контракты без привязки к Electron, Node.js, AWS SDK или ssh2.

Зависимости устанавливаются pnpm по зафиксированному lock-файлу. Версии Node.js LTS и pnpm
явно задаются в репозитории. Сборка renderer выполняется Vite, сборка процессов Electron —
electron-vite, создание платформенного пакета — electron-builder.

## Последствия

- Один стек и большая часть кода используются на трёх целевых платформах.
- Типы могут совместно использоваться между процессами без совместного использования
  реализаций.
- Размер runtime и регулярное обновление Electron становятся частью стоимости сопровождения.
- Нативные зависимости должны проверяться для каждой целевой платформы и архитектуры.
- Разделение процессов требуется поддерживать линтером, тестами и code review.

## Отклонённые альтернативы

- **Нативные приложения для каждой платформы.** Дали бы лучший доступ к платформенным API, но
  потребовали бы три реализации и усложнили согласованность поведения.
- **Tauri.** Уменьшил бы размер пакета, но добавил бы второй основной язык и иную модель
  интеграции с выбранной JavaScript-экосистемой протоколов.
- **Веб-приложение.** Не предоставляет необходимый доступ к локальной файловой системе,
  системным секретам и сетевым протоколам без отдельного привилегированного компонента.
