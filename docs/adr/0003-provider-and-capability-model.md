# ADR 0003: Провайдеры файловых систем и модель возможностей

- Статус: принято
- Дата: 2026-08-30

## Контекст

Локальная файловая система, SFTP и S3 по-разному представляют пути, каталоги, переименование,
копирование и продолжение передачи. Единый интерфейс, предполагающий POSIX-семантику, будет
либо ложно обещать операции S3, либо скрывать полезные возможности отдельных протоколов.

## Решение

Ввести общий `FileSystemProvider` для lifecycle соединения, list/stat, создания, удаления,
переименования и потокового ввода-вывода. Каждый экземпляр публикует
`ProviderCapabilities`: настоящие каталоги, права доступа, симлинки, атомарное переименование,
server-side copy, multipart upload, безопасное продолжение, время изменения и checksum.

`ProviderPath` является discriminated union и сохраняет тип провайдера; общий код не применяет
к каждому пути POSIX-правила. UI и Transfer Engine проверяют capability перед предложением или
выполнением команды. Протокольная причина ошибки сохраняется для диагностики, а наружу
передаётся нормализованная безопасная ошибка.

## Последствия

- UI может корректно скрывать или заменять неподдерживаемые команды.
- S3 не изображает настоящие каталоги и атомарное переименование.
- Провайдеры проходят общий набор contract tests, но сохраняют протокольные тесты отдельно.
- Добавление провайдера требует явного описания семантики и возможностей.

## Отклонённые альтернативы

- **Единый POSIX-подобный интерфейс.** Некорректно моделирует S3 и создаёт риск потери данных при
  составных операциях.
- **Полностью независимые API провайдеров.** Размножает логику UI и Transfer Engine и мешает
  общей очереди операций.
- **Определение поддержки через `try/catch`.** Делает UI непредсказуемым и обнаруживает
  отсутствие функции только после запуска операции.
