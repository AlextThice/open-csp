# T14–T17: очередь, Commander, профили и диагностика

## Durable queue и reconnect

`QueueJournal` хранит versioned JSON в существующей SQLite-таблице settings (`transfer-queue-v1`).
Схема БД остаётся v3: новые таблицы для этих настроек не требуются. Записываются ID операции,
типизированные пути, ID профилей/вкладок и безопасный snapshot. Provider instances, credentials,
секретные ссылки, SDK errors, сигналы и содержимое файлов не сериализуются.

Очередь сохраняется до запуска задания, перед публикацией результата, при смене конечного
состояния и штатном закрытии. Progress не вызывает SQLite write на каждый блок. После рестарта
все незавершённые задания требуют проверки; загрузка очереди не создаёт сетевых соединений.
Профили разрешаются только при явном повторе. Если профиль удалён или вкладка уже использует
другой профиль, операция отклоняется безопасной ошибкой.

После рестарта поддерживается только новый проход с нуля и политикой `ask`. Частичные файлы
`.openscp-part-*` не удаляются автоматически и не используются для межпроцессного resume.
Их можно проверить и удалить через файловую панель. Verified resume сохраняется в текущем
процессе. История completed/cancelled очищается отдельной командой, не удаляющей файлы.
Очередь ограничена 10 000 записями; для новых заданий при достижении лимита нужно очистить историю.

Ошибки классифицируются как transient/auth/conflict/permanent. Engine выполняет не более трёх
попыток с exponential backoff 250/500 мс и jitter 0,75–1,25; ожидание отменяется AbortSignal.
Политики отдельных SDK остаются ограниченными, как описано в S3/SFTP документации.
Отказ в правах/аутентификации не повторяется. Неопределённый результат final rename/close
не повторяется автоматически: пользователь видит предупреждение и проверяет назначение.
При явном повторе сбрасываются закешированные цели и снова проверяются конфликты.

## Потоки между сессиями

`remote-transfer` использует source и destination providers подключённых вкладок. SFTP ↔ S3,
SFTP ↔ SFTP и S3 ↔ S3 передаются последовательно через Web Streams с backpressure. На локальном
диске нет staging-файла. Для SFTP назначения временный файл находится на удалённом сервере;
для S3 используются условный Put/multipart complete и существующий cleanup journal.
Лимиты S3 буферов и in-flight parts не зависят от размера файла. Копирование каталога в самого
себя/потомка на том же сервере отклоняется. Локальный drag-and-drop также проходит через Engine.

Обе участвующие вкладки считаются занятыми. Закрытие показывает подтверждение, отменяет задания,
ожидает окончания отмены с конечным timeout и только затем отключает сессию. История общая,
расположена вне вкладок. При таймауте вкладка остаётся открытой с ошибкой.

## Commander и доступность

Виртуализованный grid поддерживает roving focus, диапазоны Shift, переключение Ctrl/Space/Insert,
Ctrl+A, Home/End/PageUp/PageDown и переход к папке Enter. F6 переносит фокус между панелями,
в том числе в пустую панель. Контекстные меню формируются из capabilities, поддерживают стрелки
и Escape. Горячие клавиши указаны в меню и tooltips. Dialog использует native HTML dialog для
focus trap, Escape, screen-reader имени и возврата фокуса. Ошибки HTML validation локализованы.

OS drop получает путь только через `webUtils.getPathForFile(File)` в preload, затем проходит
обычную валидацию путей в main. Искусственный browser File без системного пути отклоняется.
DnD не получает произвольного IPC, Electron или filesystem API. Экспорт файлов использует
native save dialog; renderer не задаёт путь записи.

## Профили и known_hosts

Группы и последние 20 удалённых путей хранятся отдельно от credentials. Удаление профиля удаляет
его credentials каскадно и очищает группу/recent paths. Дублирование с credential создаёт новую
зашифрованную запись, не передавая plaintext в renderer. Профиль без credential копируется
как профиль без credential. Редактирование занятого профиля запрещено.

JSON archive v1 содержит только строгую allowlist полей профиля и группу. Импорт ограничен
1 МиБ/1000 профилей, выполняется транзакционно, создаёт новые UUID и не принимает secret/token
или secret references. Imported SFTP password имеет локальный placeholder ID без credential
записи; чтение приводит к credentialRequired до настройки пароля. Private key contents никогда
не экспортируются. Пути ключей могут требовать изменения после переноса на другую ОС.

known_hosts импортируется только после просмотра файла и отдельного подтверждения. Поддержаны
обычные имена, `[host]:port`, списки имён и `|1|` hashed hosts, совпадающие с уже сохранёнными SFTP
профилями. Поддержаны обычные Ed25519/RSA/ECDSA host keys. Wildcards, сертификаты и marker lines
(`@cert-authority`, `@revoked`) не импортируются; это не полный OpenSSH trust-policy importer.
Результат показывает imported/skipped/conflicts. Существующие несовпадающие ключи не заменяются.

## Локализация и диагностика

RU/EN resources, plural forms, Intl date/size/number formats и native menu labels меняются без
рестарта. CI сравнивает полные наборы ключей и проверяет literal translation references в UI.
Сырые сообщения AWS SDK/ssh2 и stack traces остаются за IPC-границей.

`Diagnostics` хранит не более 200 локальных событий с timestamp, безопасным кодом и категорией.
Экспорт включает версии runtime/платформы, количества профилей и состояния сессий/операций.
Нет имён профилей/серверов, usernames, путей, ключей, токенов, exception messages или stacks.
Report строится по allowlist и проходит redactor; пользователь видит содержимое до сохранения.
Телеметрия и автоматическая отправка не включены.

## Проверки

Unit: журнал и рестарт без автозапуска, неопределённый commit, конечные retries/jitter, секреты
и транзакционность импорта, known_hosts conflict, redaction отчёта, RU/EN keys/plurals/formats.
Integration: реальный SFTP ↔ S3 roundtrip 256 МиБ с SHA-256 и бюджетом RSS <192 МиБ сверх baseline.
Локальный прогон 2026-09-04: около 75 МиБ прироста peak RSS; это не суммарная память Electron.
Playwright: keyboard/multi-select, local mutations/confirmation/context menu, profile import,
diagnostic export, native/live RU menus, внутренний и системный File drop, remote transfer,
restart review и close confirmation. Проверяется отсутствие горизонтального переполнения RU UI.

Live AWS, hosted CI, macOS/Linux GUI и долгие sleep/wake/network soak tests здесь не выполнялись;
это не заменяет T18–T21.
